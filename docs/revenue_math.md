# Математика расчета упущенной выручки (Talk Sensor)

Этот документ фиксирует логику расчета "потенциально упущенной выручки" (lost_revenue_rub), которая внедрена в `push_to_supabase.py`. Мы считаем только оборотные средства.

## 1. Упущенный Апселл (Кросс-селл)
- **Суть:** Если бариста не попытался предложить доп. позицию (сироп, выпечка, большой стакан).
- **Данные из LLM:** `upsell_score == 0` И `cross_sales_score == 0`.
- **Константы:**
  - Средняя стоимость позиции в допродаже = **400 руб**.
  - Средняя конверсия успешной допродажи = **10%** (0.10).
- **Формула:** `400 * 0.10 = 40 рублей` потенциальной потери за 1 диалог, где бариста промолчал.

## 2. Лояльность (Потеря удержания гостя)
- **Суть:** Если бариста не предложил завести бонусную карту (10% кэшбека). Гости с картой ходят чаще.
- **Данные из LLM:** `loyalty_score == 0`.
- **Константы:**
  - Разница в суммарных ежемесячных тратах (LTV) между лояльным (с картой) и залетным гостем = **3000 руб** дополнительной выручки.
  - Вероятность того, что гость согласился бы оформить карту, если бы ее предложили = **50%** (0.50).
- **Формула:** `3000 * 0.50 = 1500 рублей` потенциально упущенной будущей выручки за 1 проигнорированный диалог.

## 3. Отток из-за сухого сервиса или конфликтов (Churn)
- **Суть:** Если бариста нахамил, нагрубил или вообще не поздоровался/не попрощался, гость с большой вероятностью уйдет к конкурентам.
- **Данные из LLM:** `is_conflict == true` ИЛИ `live_service_score == 0`.
- **Константы:**
  - Месячная ценность обычного гостя (LTV) = **7500 руб**.
  - Вероятность потери гостя при конфликте = **50%** (0.50).
  - Вероятность потери гостя при полностью сухом сервисе = **10%** (0.10).
- **Формулы:**
  - При конфликте: `7500 * 0.50 = 3750 рублей` потерь.
  - При сухом сервисе: `7500 * 0.10 = 750 рублей` потерь.

## Применение в коде
Эти формулы захардкожены в скрипте загрузки `e:\talk\pipeline\push_to_supabase.py`. Итоговая сумма записывается в колонку `lost_revenue_rub` таблицы `dialogs` в Supabase.
